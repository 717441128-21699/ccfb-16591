# 钟表匠的轮系 · Clockmaker's Train

一个用 **React + TypeScript + Canvas + Vite** 做的修钟表解谜游戏。玩家在钟表匠工作台上从齿轮堆选齿、核对模数与理论中心距、搭建同轴齿轮和轮系，并处理月相误差、大小月/闰年凸轮、杠杆跳齿、发条力矩与擒纵摩擦。

## 运行

```bash
npm install
npm run dev
```

生产构建：

```bash
npm run build
npm run preview
```

单元测试：

```bash
npm test
```

## 页面

- **工作台页**：齿轮堆、Canvas 拖拽、固定轴孔/自由轴心、同轴叠层、拆开视图、转速与受力标签、指针表盘、即时错误标记。
- **轮系分析页**：当前工作台或经典轮系的精确分数速比、连乘公式、月相年误差、中心距判定、每个齿轮的转速/力矩/切向力/径向力。
- **关卡选择页**：六个工作台，包括第一啮、12:1 指针运动轮系、月相、日历凸轮、发条力矩和自由沙盒；进度存于 `localStorage`。
- **钟表图鉴页**：啮合、同轴、月相、万年历、力矩、擒纵说明，以及三个编订的经典教学轮系。

## 核心规则

### 1. 啮合判定

两只齿轮必须：

1. 模数相同；
2. 压力角相同（游戏统一为 20°）；
3. 位于同一夹板层；
4. 中心距满足理论值。

```text
a = m(z₁ + z₂) / 2
```

放下齿轮的瞬间会执行 `analyzeMeshes()`。模数不同或中心距偏差超过 `0.45 mm` 的“接近齿轮对”会立即在 Canvas 和分析表中标红。不同层的同轴/投影重叠零件不会被误判为错误啮合。

### 2. 精确传动比

外啮合一级：

```text
ω_out / ω_in = − z_driver / z_driven
```

完整轮系：

```text
ω_out / ω_in = ∏(− z_driver / z_driven)
```

引擎使用 `bigint` 实现不可约分的 `Frac`，所以过关判定和分析页中的 12:1、−720、945/32 等都是精确分数；小数只用于显示和物理量估算，不参与 ratio 相等判断。

### 3. 月相误差

真实朔望月取：

```text
L = 29.530588853 天
```

若搭出的周期为 `P` 天，则每年累计误差：

```text
E_year = (P − L) × 365.25 / L   （天/年）
```

游戏中包含两种编订方案：

- 经典近似：`40/8 × 59/10 = 29.5 = 59/2` 天，约 `−0.3783` 天/年；
- 精密近似：`10/8 × 54/8 × 56/16 = 945/32 = 29.53125` 天，约 `+0.00818` 天/年。

### 4. 日历凸轮与杠杆

31 齿日历环每天前进一齿。月末额外跳动数：

```text
extra = 31 − D_month
```

因此：

- 31 天月：额外 0 跳；
- 30 天月：额外 1 跳；
- 平年二月：额外 3 跳；
- 闰年二月：额外 2 跳。

日历关卡会快进模拟 2024 起 48 个月，包含 2024 闰年和后续平年二月。

### 5. 力矩、受力与摩擦

沿动力路径到下一轴：

```text
T_next = T_now × η_mesh × η_bearing × z_next / z_now
```

当前参数：

```text
η_mesh = 0.94
η_bearing = 0.985
压力角 = 20°
Fₜ = T / r_pitch
Fᵣ = Fₜ tan20°
Fₙ = Fₜ / cos20°
```

升速轮系会按齿数比降低力矩；级数过多时，擒纵端力矩可能低于起步阈值，Canvas 会显示“钟已停摆”。受力按单动力路径估算，并联分支未做功率分流。

## 经典轮系

`src/game/classicTrains.ts` 中编订了三套教学化参数：

1. **落地钟走时轮系**：`96/8 × 80/10 × 75/10 = 720`，发条盒 12 小时一圈 → 擒纵/秒轴 60 r/h；运动轮系 `12/36 × 10/40 = 1/12`。
2. **Cal. L-2953 精密月相轮系**：`10/8 × 54/8 × 56/16 = 945/32` 天，并附 59 齿经典方案。
3. **航海天文钟风格高速轮系**：`96/8 × 80/10 × 72/12 × 80/8 = 5760`。

这些是为解谜和计算编订/简化的参数，并非声称对应某一枚具体古董机芯。

## 性能做法

- 动画只跑在单个 `requestAnimationFrame` 循环中，拖拽过程中不更新 React 状态。
- 每种齿轮/缩放/DPR 组合缓存为离屏 Canvas 精灵，避免每帧重建复杂齿形路径。
- 分析只在落子、移动、删除或切换关卡后通过 `useMemo` 重算。
- 速比状态使用精确分数；动画角速度才转成 `number`。
